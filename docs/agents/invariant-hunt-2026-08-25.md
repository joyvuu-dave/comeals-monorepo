# Invariant hunt, 2026-08-25

Every sentence in `CLAUDE.md` and `docs/adr/*.md` that says never, always,
must, only, or exactly, with the code that enforces it, one path that
skips that code, and a verdict. Method: `.claude/skills/bug-hunt/SKILL.md`.
Four read-only reviewers produced the rows; the two findings were then
proved with red specs (see `bug-hunts.md`, 2026-08-25).

Verdicts: HOLDS = enforced and the skipping path cannot break it.
NOT CHECKABLE = advice, history, or a rule for people. SUSPECT = a path
where the rule is not enforced; each is discussed under "Findings".

## Findings (red specs on the branch)

1. **A rotation recolored by a delete in another month can stay stale
   for an hour.** `Rotation.recolor_community` writes `color` with
   `update_column`: no callback, no `updated_at`. The destroy deletes the
   recolored months' cache entries by hand, but a delete cannot close the
   mid-build window (`calendar_cache_race_spec.rb`), and the month's
   version — row count and max `updated_at` — does not move, so the stale
   copy serves until the hour ends.
   Red: `spec/requests/api/v1/calendar_cache_recolor_race_spec.rb`.
   Note: with colors on the cycle the recolor changes nothing, so this
   needs a rotation already off the cycle. Proposed fix: `update!(color:)`
   (or bump `updated_at` in the same statement, as `set_place_value` does).
2. **`rotations.start_date` goes stale when the rotation's first meal is
   deleted or moved.** It is recomputed only in the rotation's own
   `after_save`; a meal write does not save the rotation. `residents:notify`
   picks rotations by `start_date` (the one-week window), and
   `set_place_value` orders by it. A meal created alone after its rotation
   never sets it at all (the nightly task's `create!(meals_attributes:)` is
   what does).
   Red: `spec/models/rotation_start_date_spec.rb`.
   Proposed fix: recompute from the meal's callbacks (`after_commit` on
   Meal for `rotation_id`/`date` changes, both old and new rotation), or
   drop the column and read `meals.minimum(:date)` where it is used.

## Suspects that are rule gaps, not wrong results (no spec; David decides)

- CLAUDE.md "never pass `community:` from a rake task": the two test
  fixture tasks (`lib/tasks/test/*.rake`) pass it about 30 times. Harmless
  (`||=` and one row). Either exempt test tasks in the sentence or clean
  them.
- CLAUDE.md "never `Time.zone.today`": `db/seeds.rb` (11 sites) and
  `lib/tasks/test/seed_integration.rake` read the app zone; both are
  outside the `bin/check` grep. Dev and test data only.
- ADR 0001: money strings are typed only in the three `.ts` files;
  every store that holds `bill.amount` is `.js` with `checkJs: false`, so
  `Number(bill.amount) + 1` would pass `bin/check`. No offender today. An
  ESLint rule on `Number(`/`parseFloat(`/unary `+` in `stores/` would
  enforce it.
- ADR 0001 "new frontend code is written in .ts/.tsx by default": 25+
  new `.js/.jsx` files since the ADR, 2 new `.ts`. The doc and the
  practice disagree; pick one.
- ADR 0004: a superuser can delete their own account in one click while
  another superuser exists; the self-demotion rule covers `update` only.
  Same outcome as the case the rule forbids.
- ADR 0006: `residents/login.jsx` is a modal form outside the discard
  gate (typed email is dropped on click-outside). Low stakes.

## Also noticed

- `config/initializers/active_admin_conflict_rescue.rb:29-31`: the comment
  says the API's `after_action` sends the Pusher event; models push now.
- `Community#notify_pusher` and `#invalidate_calendar_cache`
  (`app/models/community.rb:392-404`) are dead code that bypasses
  `LiveUpdate` if anything ever calls them.
- ADR 0003 says `billing:recalculate` reads under REPEATABLE READ;
  `SnapshotRead` is SERIALIZABLE READ ONLY DEFERRABLE now.
- `/index.html` as a literal path is served by the static server on the
  admin subdomain too (same file; harmless).
- `meals.cap` has no whole-cents CHECK; it is only ever copied from
  `communities.cap`, which has one.
- Reviewer 3 marked the recolor path as covered (row 51 below); finding 1
  shows the delete-by-hand it relied on is not enough.
